built for testing, containerization, and deployment to Kubernetes.

📌 Overview

Movie Picture Pipeline is a DevOps-focused project designed to automate
the development and release workflow for a movie catalog application.

The project contains two applications:

Frontend --- A JavaScript application built with the React
framework.

Backend --- A Python API built with the Flask framework.

The application source code is located inside the starter directory:

starter/
├── frontend/
└── backend/

The goal of the project is to implement automated Continuous Integration
(CI) and Continuous Deployment (CD) workflows using GitHub Actions.

🚀 CI/CD Requirements

Frontend

Continuous Integration

The frontend CI workflow:

Runs for pull requests targeting the main branch when frontend
application code changes.

Can be triggered manually.

Runs lint and test jobs in parallel.

Runs the build job only after both lint and test complete
successfully.

Continuous Deployment

The frontend CD workflow:

Runs on pushes to the main branch when frontend application code
changes.

Can be triggered manually.

Runs lint and test checks.

Builds only after the validation jobs succeed.

Builds and tags the Docker image using the Git SHA.

Deploys the application to the Kubernetes cluster.

Updates the deployed image to the newly generated Git SHA tag.

Backend

Continuous Integration

The backend CI workflow:

Supports pull-request based validation.

Can be triggered manually.

Runs linting and tests as validation jobs.

Builds the application only after validation succeeds.

Continuous Deployment

The backend CD workflow:

Supports push-based deployment automation.

Can be triggered manually.

Runs validation before building.

Builds and tags the Docker image using the Git SHA.

Applies Kubernetes manifests to deploy the newly built image.

🧪 Frontend Development

Install Dependencies

cd starter/frontend
nvm use
npm ci

Run Tests

CI=true npm test

Run the Linter

npm run lint

Build and Run Locally

REACT_APP_MOVIE_API_URL=http://localhost:5000 npm start

Build the Docker Image

docker build \
  --build-arg=REACT_APP_MOVIE_API_URL=http://localhost:5000 \
  --tag=mp-frontend:latest .

Run the container:

docker run --name mp-frontend -p 3000:3000 -d mp-frontend

🐍 Backend Development

Install Dependencies

cd starter/backend
pipenv install

Run Tests

pipenv run test

Run the Linter

pipenv run lint

Run the Application

pipenv run serve

Build the Docker Image

docker build --tag mp-backend:latest .

Run the container:

docker run -p 5000:5000 --name mp-backend -d mp-backend

Verify the API:

curl http://localhost:5000/movies

☸️ Kubernetes Deployment

The project uses kustomize to prepare Kubernetes manifests
dynamically.

Frontend

cd starter/frontend/k8s

kustomize edit set image frontend=<ECR_REPO_URL>:<NEW_TAG>

kustomize build | kubectl apply -f -

Backend

cd starter/backend/k8s

kustomize edit set image backend=<ECR_REPO_URL>:<NEW_TAG>

kustomize build | kubectl apply -f -

The image tag used for deployment should match the Git SHA generated by
the commit that triggered the workflow.

☁️ Continuous Deployment Environment

Before testing deployment workflows, the AWS and Kubernetes environment
must be prepared.

Create Infrastructure

cd setup/terraform
terraform apply

Retrieve Terraform outputs when required:

terraform output

Configure Kubernetes Access

Run the provided initialization script:

cd setup
./init.sh

This configures the GitHub Actions IAM user for Kubernetes access.

⚠️ Important: The deployment infrastructure can incur AWS costs.
Destroy resources when you are finished working.

🔐 GitHub Actions Configuration

The deployment workflow requires AWS credentials for the GitHub Actions
user.

Create the required access keys through AWS IAM and store the
credentials as GitHub repository secrets.

The GitHub Actions workflow uses these credentials to interact with AWS
services, build and publish container images, and deploy to Kubernetes.
